# PokéMaritimes dev tooling

Run everything from the repo root with `C:\Python313\python.exe`; the commands below omit that prefix. Test output goes to `dev/out/`, which is gitignored. Engine background is in `design/mapping_reference.md`. The latest merge, published phone build, save compatibility and next-session handoff are in `design/status.md`.

After a phone publish, `dev/mobile.py --status` reports the current play file and upload state.
If it lists no synced My Boy! save, matching save-layout versions establish format compatibility,
but the publish workflow has not boot-tested a specific phone save.

## Making or editing a map
**Shared layouts and failed commands.** Copied standard interiors initially share their template's
terrain. `mapgen` and `fix_attrs` refuse changed bytes when other maps use that same block file
(even through different layout IDs); `--force` does not override this. First use
`dev/unique_layout.py <Map> --apply`. An unchanged rebuild is safe and still allowed. Porymap
edits bypass the Python guard, so detach a room before editing its shared terrain there too.

`mapgen`, building/interior creation, event application, area naming, layout detachment and
attribute batches roll back their declared source files on exceptions or Ctrl-C. Newly created
room/layout folders are removed, and existing bytes are restored. Previews in `dev/out` remain
available to inspect. Individual layout/JSON replacements also avoid truncating the live file.
Run one authoring command at a time; rollback is not a power-loss/process-kill journal and does
not replace git. Building plans reserve every generated floor and map constant together and
refuse existing orphan folders/registered names, before application.

1. **Get a sketch.**
   - From an existing map: `dev/mapgen.py extract <Map>` writes `design/maps/<Map>.txt`.
   - For a new design: write a design script like `design/maps/route203_design.py` or `ledgelab_design.py`. For a brand-new map, run `dev/new_map.py` first. `route203_design.py` is the worked example of ledges on a real route (a levee terrace and a wooded bench).
2. **Edit the sketch.** Each character is a terrain type: `.` grass, `,` tall grass, `=` path, `:` sand (a beach where it meets `~`), `~` river/sea, `o` pond, `T` forest, `r` rock in water, `*` flowers, `b` boulder, `y` sapling (a vertical run of 2–3), `s` sign post (its text is a sign event, below), `v` `<` `>` ledges (below), `B` a building stamp's cell (below), `H` a plank bridge's deck (below), `^` a cliff wall and `%` stairs up a cliff (below, with the `// level:` lines), `#` keep the existing block. Design scripts draw natural forests and open ground with `mapkit/landscape.py`, terraces with `landscape.terrace` and place buildings with `Sketch.place` (below).
3. **Preview.** `dev/mapgen.py build design/maps/<Map>.txt [--fresh]` is a dry run. It runs the checker on the result in memory and writes `dev/out/<Map>_preview.png` and `_preview_overlay.png`.
   - It also reports how many cells differ from the current `map.bin`, and where. `_preview_diff.png` shows before and after side by side, cropped to the change, with changed cells outlined. When you edit an existing map, check that the change stays where you meant it to.
   - Use `--fresh` for new designs. It ignores the old map's tree placement.
   - Without `--fresh`, trees are kept on the existing 2×2 grid. A grove moved by an odd number of tiles loses trees (`dropped_tree_cells` in the report). Move groves by even amounts.
   - It prints two **landscape** numbers, before and after, for the whole map and for the changed area: the longest straight forest edge, and the largest square of bare grass, each with where it is. Lower is more natural.
   - It prints the **routes**, before and after: for each pair of edge connections, the steps across and the tall grass that can't be avoided, and the reachable tall grass. A redesign that should play the same keeps these close.
   - On a map with connections it writes `_preview_context.png`: before above after, with strips of the neighbours, so the seams can be judged.
   - It warns (`WARN reach`) when open ground a walker could reach before is now cut off: a new pocket.
   - **Terrain guard:** the grammar repairs a forbidden join by turning the lower-ranked cell into grass (a tree beside sand clears the sand). If a repair would overwrite terrain the current map *already has* as the sketch draws it, the build prints `GUARD terrain` and counts it as a new error. This is how a hand-painted join (HomeTown's lane between trees) gets damaged, so keep such joins as `#`. `extract` now does that by itself: it keeps both sides of a join the grammar forbids (trees whole), plus any neighbour a compile wouldn't put back.
4. **Apply.** `... --apply` writes `map.bin`, but only if the result has no *new* checker errors (a terrain guard hit counts as one). Errors the map already had don't block a rebuild; `--force` overrides.
5. **Build, then play-test.** Use `fastbuild.py`, then `autowalk.py`, `tests/conformance.py <Map>` and `shoot.py`. If the map has ledges, also run `tests/ingame_ledges.py <Map>`.

How compiling works:
- Forest becomes whole 2×2 trees.
- Forbidden terrain pairs get a grass margin. Each repair is reported.
- Every cell gets the metatile vanilla uses in that neighbourhood. Unseen neighbourhoods fall back to a naive-Bayes vote.
- Ledges are assembled from vanilla's pieces by shape (`mapkit/ledges.py`), not voted on.
- Collision and elevation come from vanilla's defaults.

### Ledges
Draw a ledge as a line of the character for the direction the player jumps. The high ground is behind the arrow.
- `v` jumps south. Draw it as a horizontal row.
- `<` jumps west and `>` jumps east. Draw them as vertical columns.
- There's no `^`: `gTileset_General` has no north-facing ledge.

The compiler picks each piece from the shape:
- **Ends:** end caps.
- **Corners:** where a column meets a row, it uses the plateau corner (Route 116) or the one-tile stair step (Routes 101 and 103). A corner may be drawn with either character.
- **Running on:** a ledge running off the map edge, or into a kept `#` cliff or wall from the secondary tileset, has no cap. This is what vanilla does.

`design/maps/LedgeLab.txt` shows every piece.

The sketch is refused, with the cells to fix, in these cases:
- Ledges branch, stack, or are a single tile.
- A column mixes `<` and `>`.
- A usable ledge lands on a tree, water, a solid tile, or off the map. The game never checks the landing tile, so this would be a real bug.

A ledge with nothing walkable behind it can never be jumped. That's allowed (vanilla's cliff ledges are like this) but reported as a warning.

The checker (`check_maps.py`) adds two map-level checks for any map, hand-painted ones included:
- **`ledge`:** a reachable jump that lands on a solid tile or in water.
- **`trap`:** tiles a player can walk or jump into but never leave. This is an ERROR. If Surf is the only way out, it's a WARN.

Ways out are connections and warp triggers. On a map whose only warp is a `new_map.py` spawn point, returning to the spawn also counts. Only one vanilla map has a trap: Shoal Cave's ledge pocket. It's confirmed in-game and listed in `mapkit/baseline.py`.

### Shores (riverbanks, lake shores, beaches)
Where `~` water meets land, `mapkit/shores.py` builds the edge from the shape, like ledges. It doesn't use the learned vote, which only knew straight banks and drew plain edges on coves and corners. `gTileset_General` has the same structure in two materials:
- **Grass bank:** `189` top, `190`/`192` sides, `188`/`18A` corners, `178`/`179` bank ends, `198`/`19A` inner corners, and `002` on the grass below the water.
- **Beach:** draw `:` sand against the water. The pieces are `12C`, `123`/`125`, `146`/`145`, `11B`/`11D`, `12D`/`12B`, and `11C`/`13D`/`13E` on the sand below the water. On its land side the sand keeps the sand patch's grassy rim.
- **Rocks:** `r` is a 2×2 rock standing in water (`150 151 / 158 159`). It must be a whole 2×2 with water on every side.

Tips for natural shapes (see `design/maps/route203_design.py` and `shorelab_design.py`):
- Vary the width, and change the bank one row at a time, every two to five columns. Long flat runs and big jumps look rectangular.
- Give promontories a rounded tip (4 → 5 → 4).
- For a beach in a bay, let the water bulge into the sand. Run the sand one tile past the water on each side, so the ends get `13E`/`13D`.

The compiler refuses shapes the tiles can't draw, naming the cells:
- water one tile wide between two side banks;
- a grass bank that turns into a beach at a corner (start the beach on a straight stretch);
- water squeezed between a side bank and the opposite corner;
- half a rock, or a rock touching land.

Kept `#` tiles and pond water count as "no land", because vanilla draws those edges on the object itself. `extract` keeps (`#`) any shore cell that a compile wouldn't reproduce exactly (special water such as waterfalls, vanilla's unusual joins), so extract → compile never changes a shore block. `design/maps/ShoreLab.txt` uses every piece.

### Bridges
`H` is a plank bridge's deck carrying a road north-south over river water (`mapkit/bridges.py`): vanilla's Route 104 bridge (Rustboro `350 351` north end over the bank's water row, `34E 34F` deck over open water; the grass under the south end loses its bank, `001`). The planks are opaque edge to edge, walkable at elevation 3 with `MB_REFLECTION_UNDER_BRIDGE` (the player's reflection shows in the planks below); a surfer can't climb onto the deck or pass under it, as on Route 104.
- **Draw** a strip of `H` exactly two columns wide over every water row of the crossing, where the river runs east-west for at least a column either side, with grass at both ends (the road meets the deck across the same one-tile grass margin it keeps from water). For the shores, the grammar and the learned rules the deck reads as water, so the banks run on beside it. `design/maps/woodstock_design.py` is the worked example (Main Street over the Meduxnekeag).
- **Refused**, naming the cells: a strip that isn't two wide or whose rows don't line up; a crossing where the river doesn't run east-west (a deck cell with land beside it); no grass (or kept `#`) at an end (a boulder, sand, the map's edge); a tileset without the pieces, with the command that copies them: `dev/tile_import.py bridge <tileset> --apply` (Petalburg has them; Rustboro is their own tileset).
- **Extract** recognises a deck whose strip resolves exactly; anything else stays `#` (Route 104's turning bridge over pond water).
- Not yet: a horizontal deck over a river running north-south (Route 104 has the pieces: `344 346 347 34C 34D 333 334`), and a bridge a surfer passes under (Route 110's and Route 119's elevation-15 bridges).

### Cliffs and terraces (levels)
Terrain that steps up is drawn with **levels** and **walls** (`mapkit/cliffs.py`), from vanilla General's brown rock family (the pieces Routes 104, 116 and 120 build their bluffs with). Every sketch cell has a level, 0–9: `// level: 0001112...` lines in the sketch file, one per row (none when the map is flat). Levels are a design notion: walkable ground stays at elevation 3 and walls block by collision.
- **`^` is a wall** cell (solid), **`%` stairs** (walkable). A wall belongs to the terrace it bounds, so its level is its high side's. The camera looks north, so a terrace shows a **face** on its south side (as many rows as you draw: one row `079`; taller `07C`, `0A9`..., `091`), on its north side the grass terrace's **edge line** (vanilla's Safari Zone: `068 0D3 002 ... 002 0D4 06A`; a stretch of two is `068 002 0D4 06A`, and a north inside corner is the line too, the flank above resting on it), a **flank** on each side (`070` west, `072` east), and the corners between them, convex and concave. The resolver picks every piece from the wall cell's neighbours: low, high or wall (`cliffs.piece_for`; the table is in the module docstring and `design/mapping_reference.md` §16).
- **Draw with the helpers** (`mapkit/landscape.py`): `terrace(sk, area, level, face=2)` raises an area and walls its edge (raise low terraces first; a higher one inside a lower one walls itself against it); `stairs(sk, x, y, width)` cuts stairs, one or two wide, down a south face from its top row; `cutting(sk, cells, level)` takes a road through a wall: the cut cells take the lower level, so the walls end in corners on both sides, and the road climbs (**a graded road**: two path cells one level apart, one of them beside a wall). `cliff_clearance(sk)` keeps planting off the stairs. `design/maps/clifflab_design.py` shows every piece and way between levels; `route202_design.py` is the worked example on a real route.
- **Ways between levels:** stairs (south faces only: General has no side or north stairs), ledges (a ledge in a face or a flank runs under the walls beside it, no cap), and graded roads through cuttings. Edge lines and flanks can't be climbed.
- **The rock rim `069` is not drawn** (nor `0BE`/`0BF`): vanilla puts it only over rock-topped plateaus (Routes 111, 116), never over grass, and it read as a rock strip floating on the lawn (Tom's phone play). Vanilla's `002` line is walkable grass held by an elevation change; ours is solid like every wall (`cliffs.is_cliff_block` tells the two apart). Rock-topped plateaus are a later item.
- **Checked against vanilla** (`tests/cliff_pieces.py`): every pair of pieces side by side, and every piece against the ground on each side of it on every built map (a pairing vanilla never draws must be judged in its `GROUND_OK` with a reason).
- **Refused**, naming the cells: walkable ground side by side at different levels (put a wall, a ledge or stairs between them, or a graded road through a cutting); a wall touching water (leave a tile of ground at its foot); a wall with low ground on both sides; low ground on two of its diagonals (pinched); stairs that aren't in a south face, are three wide, or lack high ground above or low ground below; a face more than two rows tall ending against a flank, or two rows tall and one column wide between flanks (vanilla has no pieces for either).
- **Perspective matters for drama:** the camera sees faces only on terrain that rises to the north. Where the ground rises away from the player to the south or south-west (Route 202's upland), only rims show: plant forest right up to the crest so the rim reads as the slope's edge, and step scarps in runs of several tiles, not single-tile staircases.
- **Extract** keeps cliffs as `#` (their levels aren't recovered yet); extract → compile leaves every cliff block as it was. To the learned rules a wall reads as grass, so its neighbours are plain grass, and the rules never draw stairs (`0AF`/`0CF`, which vanilla labels as grass) in open ground.

### Saves and redesigns: world revisions
A save standing on a map that a later build redesigns would CONTINUE at its old coordinates, with the map's people where it saved them and its saved view of the old terrain pasted around the player. When a milestone redesigns a map saves may stand on, add a row to `sWorldRevisions` in `src/overworld.c` (revision, map, safe tile: the map's heal location if it has one, else x, y) and raise `MARITIMES_WORLD_REVISION` in `include/constants/vars.h` to it. On CONTINUE, a save whose `VAR_MARITIMES_WORLD_REVISION` is below the row's revision and that stands on the map continues through vanilla's continue-game warp (a full map load) to the safe tile; coordinate warps on the map move there, a respawn point on the map is re-pointed at its current heal location, and the var becomes current (a new game starts on it). Any save made before the current revision also drops its saved view of the terrain, wherever it stands: the view reaches into connected maps' strips, so a save beside the redesigned map's seam would show the old map there. Saves inside the map's rooms need nothing: redesigns keep warp ids. Test: `tests/ingame_world_revision.py` (`--old-rom <rom.gba>` with its `.map` beside it adds real saves from an older build, e.g. the last phone build from Drive's `builds/`).

### Seams: making two maps read as one landscape
What the player sees across a map edge is the engine's business, so `mapkit/seams.py` models it (engine facts: `design/mapping_reference.md` §17) and the tools hold seams to it:
- **The checker warns** on every map: `seam_tileset` (the neighbour's strip holds metatiles of another secondary tileset, which this map draws with its own: wrong graphics), `seam_person` (a person or item ball near the seam: invisible from across it, it pops in the step the player crosses; keep people 7 columns from a side seam, 6 rows from a top seam, 4 from a bottom one), `seam_tiles` (pairs across the seam vanilla never draws side by side: a cut tree, a cap with no tree under it, a bank or road that changes shape at the line), `seam_border` (the same against the border's trees or edge water past an edge with no neighbour).
- **`corridor.py check` makes them errors** on every join the plan has built (interim joins it will replace are listed as connection changes instead). A pair judged to read right in a render and in-game goes in the map's `seam_ok` list in `corridor.toml`, `[x, y, why]`.
- **The compiler sees the neighbours.** `mapgen build` passes `seams.outside_labels`: edge cells are tiled for what lies across each connected edge, and a tree is cut by a connected edge only where the neighbour holds its other half (a design that leaves an odd column of forest at a seam loses it: `dropped_tree_cells` and a `reach` warning say where). After changing a map beside a built neighbour, rebuild both until a rebuild changes nothing (two rounds did for the start valley).
- **The compiler sees the border too.** Past an edge no neighbour covers, `mapgen build` passes `seams.border_labels` (the border's 2x2 trees, or the edge water carried on): edge cells get their caps and shadows right beside the border's trees, and a grove touching such an edge is tiled on the border's grid where it can be (its inner fringe gives up a row instead, so the walkable area there grows by a row, never shrinks). Where nothing can line up, the tree is still cut at the edge (a soft rule: never a strip of grass against the border), and the checker warns `seam_border`. A grove that touches both the border and a neighbour's seam may need two grids at once; the seam wins and the design has to move the forest's edge (Woodstock's south-west and far bank, HomeTown's south-east today). Check the route numbers after a rebuild: a fringe that gives up a row can open a way.
- **Water at an edge with no neighbour** runs on into the margin in-game, banks and verges included (`OW_EDGE_WATER`, §17), so a brook out of the hills or a river toward a map not built yet needn't end at the edge. Only a side with no connection at all gets it: water on a partly connected side still meets the border beyond the neighbour, so keep it inside the shared stretch. Nothing to do in a design.
- `render_map.py --context` draws what the engine draws: neighbours in this map's tilesets, the border pattern elsewhere, edge water carried into it.

### Forests, open ground and flora
**Flora pieces** (`mapkit/flora.py`) are built by shape, from vanilla's General tiles:
- `*` flowers (`004`), walkable.
- `b` a boulder (`0E0`), solid.
- `y` a sapling: a vertical run of 2 or 3 `y`, drawn as `00E` crown top / `0C6` crown middle / `017` trunk. You walk behind the crown top; the rest is solid.

Each piece stands on plain grass only. The compiler names the cells where grass would get an edge tile instead: right above a tree (canopy overhang), right below water (the bank), or beside a path rim. A ledge may land on flowers or a crown top, but not on a boulder or a trunk. `design/maps/GroveLab.txt` uses every piece.

**Design helpers** (`mapkit/landscape.py`). You compose: where the groves, clearings, meadows and accents go. The helpers draw vanilla's small-scale shapes, deterministically from a seed. Masks are sets of cells; combine them with `|`, `&` and `-`.
| Helper | What it draws |
|---|---|
| `forest_edge(x0,y0,x1,y1, open_side, amp, seed)` | Forest whose edge facing `open_side` recedes 0..amp tiles along a stepped profile: flat for 2–5 tiles, then a step of a tree, often continuing as a diagonal staircase. |
| `blob(cx,cy,rx,ry, seed, wobble)` | A rounded patch with a few smooth lobes: a grove, a clearing (subtract it), a meadow. |
| `plant(sk, mask, area, parity, keep_clear)` | Replants the forest in `area` to cover `mask`, in 2-row bands. Fringe runs start flush with open ground at any alignment, giving vanilla's staggered edge trees. Enclosed runs stay on the tree grid given by `parity`, the (x, y) parity of the trees around the area. A tile left over goes to an open end (a nook) or becomes a sapling, never a pocket. |
| `meadow(sk, mask, seed, tufts)` | Tall grass over the mask, plus a few stray tufts just outside it. |
| `sapling_stand(sk, mask, seed, density)` | A young grove of 2–3 tall saplings in a staggered rhythm. Trunks never stand side by side, so it never closes into a hedge. |
| `flower_bed(sk, x, y, n, seed)`, `nestle(sk, area, n, seed)` | A compact bed of flowers; boulders tucked into the forest's inner corners. |
| `around`, `cells_of`, `ledge_clearance` | Build `keep_clear` sets: the trail and its margin, ledges with their approach and landing tiles, the seams. |

Tips (see `design/maps/route203_design.py`, milestone 6 section, and `grovelab_design.py`):
- Pass every helper the same `keep_clear`.
- Give `plant` the tree grid of the forest you are editing. Route 203's southern forest starts on an odd row, so it uses `parity=(0, 1)`.
- Keep each `plant` area to whole 2-row bands. Don't let two `plant` areas overlap: each one clears the old forest inside its area.
- Check that the diff report's box stays where you meant, and read the `WARN reach` line.
- Vanilla's accents are sparse. Use a few flower beds where a trail opens out, and a few boulders per screen.
- For a wooded route, start from forest everywhere and carve clearings (`blob`s) off the road, rather than placing groves on open grass; it reads as "through the woods". See `design/maps/route201_design.py`.
- Keep hand-painted pieces (a cliff, a seam's trees) as `#`. `plant` treats a kept block as closed, so it never leaves a leftover tile against one. Put a whole tree on either side of a `#` box, never half of one.
- Trees never touch sand (`:`) directly; the grammar would clear them. Give a road a one-tile grass verge (`around(ROAD, 1)` in `keep_clear`), and keep the trees beside a road's seam gap as `#`.

### Visual rules: does it read like vanilla?
The kits make each cell a metatile vanilla would use beside its neighbours. `mapkit/composition.py` judges what the eye sees at a few tiles' and a screen's distance, against vanilla's own maps. The findings and numbers are in `design/mapping_reference.md` §18.
- **`dev/terrain_report.py [Map...]`** prints each map's report card and writes `dev/out/terrain/<Map>.png` with the findings drawn on it. With no map named, it reports every Maritimes outdoor map. `--calibrate` re-measures vanilla into `mapkit/composition_bands.json` (after changing a rule; `tests/terrain_rules.py` fails while the file is stale). `--vanilla` prints vanilla's maps rule by rule.
- **Strict, `pairs`:** two General metatiles side by side that vanilla never draws in that direction (a sapling against a tree, a one-wide lane's ragged edge, a cut tree). The checker warns (`visual_pairs`) and `mapgen build` lists them. Fix the design, or judge the pairing in `composition.JUDGED` with a reason after checking it in a render and in-game.
- **Guides:** staircases, straight edges, rectangular tall grass, tall grass away from cover, free-standing tree rows, flower beds, bare screens, open space. Each is reported against vanilla's band for the map's kind (route or town): `unusual` outside p10..p90, `beyond` past anything vanilla does. They guide; they don't refuse. When a finding is meant, say so in the design script: `sk.accept("grass_rect", "hay fields are fields")` (a `// accept:` line; an unknown rule is an error).
- **`mapgen build`** prints the visual rules before and after, beside the landscape and route numbers.
- **Finishing passes**, last in a design script so that nothing else moves: `ls.widen_paths(sk)` (no one-wide lanes), `ls.loosen_flowers(sk)` (a route's flowers as singles), `ls.uncrowd_saplings(sk, hold={...})` (no sapling against a tree; name a sapling that closes a gap in the woods in `hold` and its trunk becomes a boulder). Read the route numbers and the reach line after each: a sapling's trunk is solid, and removing it can open a way. For new designs, `ls.sprinkle(sk, x, y, n)` scatters single flowers round a spot (`flower_bed` is a town garden's).
- **The ratchet** (`tests/terrain_rules.py`, in the gate): the corridor maps' odd pairs may only go down, and a guide may not newly fall outside vanilla's band unless the sketch accepts it. Lower the numbers when a redesign fixes something.

### Buildings (stamps)
A **stamp** is a whole vanilla building, cut from a vanilla map and copied block for block (metatile, collision, elevation). The catalog is `dev/mapkit/stamps.toml`; `dev/buildings.py list` and `sheet` show it:
| Stamp | Size | Fits | Room behind the door |
|---|---|---|---|
| `pokemon_center` | 4×4 | any General map | a working Center: the nurse heals, entering sets the respawn point, the cable club upstairs |
| `mart` | 4×4 | any General map | a working Mart: the clerk sells a stock list |
| `gym` | 6×5 | any General map | Rustboro's gym hall, emptied (a placeholder) |
| `house_small`, `house_small_wide` | 4×4, 5×4 | any General map | a one-room house |
| `house_oldale` | 4×4 | Petalburg maps | a one-room house |
| `house_two_storey`, `house_two_storey_left` | 5×6 (with a doormat) | Petalburg maps | a house with an upstairs room |
| `lab` | 7×6 (with a doormat) | Petalburg maps | Birch's lab, emptied |
| `house_wide` | 8×5 | Petalburg maps | a house (its garden and hedge are part of the stamp) |

**Placing one.** In a design script: `sk.place(p, "pokemon_center", x, y, "Woodstock_PokemonCenter_1F")`, with (x, y) the stamp's top-left; it returns the door's position. It draws the cells `B` and writes the line `// stamp: pokemon_center @ x,y -> Woodstock_PokemonCenter_1F` into the sketch, which is what `mapgen` reads. `design/maps/townlab_design.py` is the worked example (every stamp, paths from each door to the street). The compiler refuses, naming the cells: a stamp off the map, two that overlap, a Petalburg stamp on another tileset, a cell of a stamp drawn as anything but `B` (or `#`, keep the current block), a `B` no stamp covers, and a door that doesn't face walkable ground (or a doormat nothing walkable leads onto). Around a building the terrain is tiled as if beside a lawn, which is how vanilla's buildings stand.

**Doors and rooms** (`mapkit/buildings.py`). `-> <Room>` names the map behind the door. `mapgen build` prints a `doors:` plan and `--apply` carries it out:
- **The room exists** and a warp on this map leads into it: that warp moves to the door. Its index stays, so the room's exits stay right: a building moved in a redesign keeps its room, its people and its warp ids (TownLab's Center was moved this way).
- **The room doesn't exist:** it is copied from the stamp's interior template (`mapkit/interiors.py`; all floors, in `gMapGroup_IndoorMaritimes`) and a warp to it is appended. A template with an upstairs needs the ground floor named `<Base>_1F`; the upper floors become `<Base>_2F`. The dry run lists the room as "(created on --apply)".
- **A Pokémon Center** also gets a heal location named for the map (`HEAL_LOCATION_<MAP>`, appended to `src/data/heal_locations.json`, the tile outside the door), and keeps it beside the door when the building moves. One Center per map.
- Refused: two doors naming one room, a room that exists but belongs to another map or door, a room two warps lead into, a two-floor room named without `_1F`, a second Center (or a renamed one: its heal location still exists), a warp that would end up inside a building, and a build that removes a door still holding a warp or outside a Center's heal location (a building dropped from the sketch). Deleting a warp renumbers the ones after it, and rooms find their door by index, so the tool never deletes one: keep the building, or remove the warp and its room by hand. `--force` doesn't override door errors. A stamp without `-> <Room>` is a dead door (the checker warns).
- A copied Center or Mart keeps its own music (`MUS_POKE_CENTER`, `MUS_POKE_MART`); a house takes the town's.

**The rooms that work.** A copied Center's ground floor has the nurse (her script calls `Common_EventScript_PkmnCenterNurse`; she stays the first object, because the heal location names her local id), sets the respawn point on entry, and keeps vanilla's shared cable club upstairs. A copied Mart has the clerk; its stock (`MART_STOCK`: Poké Ball, Potion, Antidote, Paralyze Heal, Awakening) is a `mart` block in the room's `scripts.pory`, written once and then the designer's to edit. Other rooms are empty, for `dev/events.py` to furnish with people (it keeps the nurse and clerk as hand-placed events and appends after them).

**Extract** recognises catalog buildings on a map (their solid cells must match exactly; a roof's top row blended with a tree behind it is kept as `#`) and writes them as stamps with the room their door leads to: HomeTown's two houses, Woodstock's three buildings, every building on Littleroot, Oldale and Petalburg. So a rebuild can move a town's buildings and keep their rooms. **Adding a stamp:** append an entry to `stamps.toml` (source map, top-left, shape, interior template, kind); `tests/stamp_pieces.py` checks it.

## People, signs and items
A spec per map (`design/maps/<Map>.events.toml`; `Route201_1.events.toml` and `Woodstock_2.events.toml` are the worked examples outdoors, `Woodstock_Lab.events.toml` indoors) lists the map's people, trainers, signs, things to inspect, item balls and hidden items. The spec owns those events. Anything placed by hand in Porymap is left alone (shown as `[hand-placed]`), so the two can be mixed.
```toml
map = "Route201_1"
replaces = ["LittlerootTown_EventScript_BrendansHouseSign"]           # optional: hand-placed events to take over
[[sign]]         name = "RouteSign", at = [12, 3], text = "..."           # two lines, like vanilla's
                 facing = "up"                    # optional: readable only from below (default any)
[[inspect]]      name = "FieldNotes", at = [7, 1], text = "..."           # furniture, a desk, a poster: any length
[[person]]       name, at, gfx = "OLD_MAN", facing = "left", text
                 facing = "wander", range = [2, 2]                    # optional: a wanderer
                 gift = "ITEM_ORAN_BERRY", count = 1, after = "..."   # optional: gives it once
[[trainer]]      name, at, gfx, facing, sight = 4, class = "Bug Catcher", trainer_name = "ROSS",
                 party = ["Caterpie 3", "Weedle 3"], intro, defeat, after
[[item]]         name, at, item = "ITEM_POKE_BALL"                    # an item ball
[[hidden_item]]  name, at, item = "ITEM_POTION"
```
`facing` is `down`, `up`, `left`, `right`, `around` or `wander` (with `range = [rx, ry]`, each 1–4; default `[1, 1]`. The game reads a 0 as *no limit* on that axis, so the tool refuses it). A gift person says `text`, gives the item and says `after`; later talks only say `after`. With a full bag they give nothing and offer it again next time. In dialogue, a blank line starts a new message box, and Poryscript's `format()` wraps the rest. Straight double quotes become “ ” (the charmap has no `"`). `[[inspect]]` is text read from a solid tile that has no sign post: a desk, a machine, a mailbox; it wraps like dialogue. Bookshelves, PCs and TVs already have vanilla's text (a tile behaviour), so they need no event. `replaces` names hand-placed events (by script or local id; `"<name>@x,y"` when several share a script) that the spec removes, so a spec event can take their tile: HomeTown's mailbox ran Littleroot's house-sign script. Each entry must match exactly one event, and a person can't be removed while hand-placed people follow it, because local ids are positions and hand scripts use them. A trainer's Pic, Gender and Music follow the first vanilla trainer of its class unless the spec gives them.

The workflow:
1. **Terrain first.** A sign needs a sign post under it: draw `s` in the map's design script and rebuild with `mapgen` (one cell; check the diff). On a hand-painted map without a design script, use `dev/mapgen.py patch <Map> s@x,y` (Woodstock's town sign).
2. **Dry run:** `dev/events.py build design/maps/<Map>.events.toml`. It refuses bad placements, naming them: out of bounds, two events on a tile, people on solid ground or water, a sign without a post, a sign over two lines, unknown graphics/items/species/classes. Then it prints every event with the tiles it can be triggered from, each trainer's reachable sight, and the ids it would allocate. It also runs the checker on the unsaved map, prints the route numbers before and after (a trainer on the road shows up as `can't avoid <trainer>`), and writes `dev/out/<Map>_events.png`.
3. **Apply:** `--apply` refuses new checker errors (`--force` overrides). It writes the owned events into `map.json` (after the hand-placed ones, whose local ids don't move) and the scripts into a marked block in `scripts.pory`. A room made by `add_interior.py` has no scripts at all (a stub `scripts.inc`); the tool starts its `scripts.pory`. A map with real assembly scripts must be converted by hand first. Each trainer gets an id appended to `opponents.h` and its party in `trainers.party`. Each item ball, hidden item and gift takes the next flag of the Maritimes block in `flags.h`, `(MARITIMES_FLAGS_START + n)`. Re-applying an unchanged spec changes nothing; ids are never reused or moved.
4. **Build and test:** `dev/fastbuild.py`, then `dev/tests/ingame_events.py <Map>`.

What the checker knows (`mapkit/events.py`, engine facts in `design/mapping_reference.md` §12):
- **ERROR `people`:** an exit (a warp, or a connection's edge) is reachable when nobody stands in the way but not with the map's permanent people at home.
- **WARN `people`:** ground reachable only through people. A person, item ball or sign with a script that nobody can reach to talk to, pick up or read (position, elevation, facing). A wanderer that can cut off an exit while it stands somewhere in its range (each tile is tried; vanilla does this in small houses, so it's a warning: the wanderer moves on).
- **INFO:** a trainer nobody can walk into the sight of (battles only when talked to); an event reachable only with Surf.

People's names follow the map: `LOCALID_<MAP>_<NAME>`, `<Map>_EventScript_<Name>`, `TRAINER_<MAP>_<NAME>`, `FLAG_HIDDEN_ITEM_<MAP>_<NAME>`, `FLAG_ITEM_<MAP>_<NAME>`, `FLAG_<MAP>_<NAME>_GIFT`.

**Id budget.** Trainer ids and saved flags are global and never move. Milestone 9 raised `MAX_TRAINERS_COUNT_EMERALD` to 1376 (520 ids free) and added a Maritimes flag block after the daily flags; milestone 11 sized that block for a whole region (768 flags) and added a 256-var story block in SaveBlock3 (`design/save_format.md`). The block flags are shared: `events.py` takes item and gift flags from it, `save_ids.py` story flags. The dry run prints what's left after each new id, and `dev/tests/id_budget.py` checks the whole budget. To grow a block, raise the constant (`opponents.h`, `MARITIMES_FLAGS_COUNT` in `flags.h`, `MARITIMES_VARS_COUNT` in `vars.h`). That changes the save layout: the build stops until `dev/save_layout.py --update` bumps the version, and old saves are refused. Prefer one generous raise to several small ones, and run `tests/ingame_save.py` afterwards. Once the Hoenn maps are removed, their trainer ids, flags and vars can be reclaimed too.

## Test suites
**The gate is `dev/regression.py`** (the steps: `--list`; the merge checklist in `design/status.md`). What it guarantees:
- **No silent passes.** A step passes only on exit code 0 *and*, where it claims coverage, output showing that coverage: conformance must execute every planned comparison (a warp that lands elsewhere or errors is a failure, not a skip), doors must complete round trips, TownLab must exercise both a Center and a Mart, encounters must have a real battle, shores and flora must count a positive, fully passing total, and each events spec's dry run must show no drift and 0 checker errors. The tests themselves fail on zero coverage (no maps, no doors, no cases, `--samples 0`, `--battles 0`). Deliberate exclusions are printed by name: ledge tours on maps with wandering people, `--surf 0`. `reconstruction` and `route_metrics` are **OBSERVED** (measured, no threshold), never counted as passes.
- **Evidence.** Each step's counts (`532/532`, `114/114 checks on 7 maps`, `12 wild battles`) are printed and kept in `report.json`; quote them in a handoff instead of retyping numbers. The report says when the tested tree had uncommitted changes.
- **No emulator interference.** Each `Emu` launches mGBA with a private copy of `bridge.lua` on its own free port and checks a per-session token on connect, so a second emulator (another test, `mobile.py`) can't take over its socket. Automated tests copy the ROM, map and save into their own `dev/out/emutest-*` folder (`prepare_rom`), removed when the test exits. Steps run one at a time; a lock (`dev/out/regression/run.lock`, held by the OS) refuses a second run, and a step that times out or is interrupted is killed with its whole process tree, so no orphaned mGBA slows the next test. The runner warns when other mGBA processes are open, and sweeps scratch folders left by killed runs (older than 6 hours).
- `tests/harness_guards.py` (no emulator) proves the above with negative controls: zero-coverage and relocated-warp paths fail, the runner refuses empty success, a timed-out step's child process dies, the lock holds. `tests/emulator_isolation.py` runs two live emulators side by side and checks neither disturbs the other.

The interactive `dev/playtest.py` keeps its fixed `dev/out/test.gba` slot so `--continue` works across commands.

`tests/authoring_safety.py` runs real writers in disposable fixtures under `dev/out`: shared
layout refusal and explicit detachment, floor/constant collisions in both placement orders,
successful room creation and return-warps, and byte-for-byte recovery after late failures
(including event IDs and Ctrl-C). It never edits the game's maps.

`tests/ingame_respawn.py` uses three actual trainer defeats without test mode: fresh home,
an all-zero respawn repaired on CONTINUE, and a saved Center choice. It checks arrival,
healing and returned control using a disposable save in its own `dev/out/emutest-*` folder.

## In-game dev hooks (non-release builds only)
`DEBUG_DEV_BRIDGE` in `include/config/debug.h` enables `gDevBridge` in `src/field_control_avatar.c`. Python uses it to warp anywhere, set and read flags (`Emu.set_flag`, `Emu.get_flag`), give the player a Pokémon (`Emu.give_mon`), count an item in the bag (`Emu.bag_count`), read and set vars (`Emu.get_var`, `Emu.set_var`), save the game (`Emu.save_game`, as the start menu does; `link=True` as a link save does), and wait until the player has control. `Emu.objects()` lists each object's local id and position.

`WE_FLAG_NO_ENCOUNTER` and `OW_FLAG_NO_TRAINER_SEE` are assigned to unused flags. `Emu.test_mode()` sets them for movement-only tests, and also sets `FLAG_SYS_POKEMON_GET` so story gates (HomeTown's exit) are open; `test_mode(trainer_sight=True)` leaves trainers able to see. Other helpers: `Emu.flee_battle()`, `Emu.win_battle()` (first move every turn), `Emu.advance_text()`, `Emu.has_control()`, `Emu.facing()`, `Emu.object_at(x, y)`, `mgba_bridge.flag_id(name)`. `Walker(e, on_interrupt=e.flee_battle)` walks with wild battles on, re-planning after each one. It plans around people and, by default, around every trainer's sight (a trainer battle can't be fled).

Map scripts may be written in Poryscript (`scripts.pory`). `fastbuild.py` copies the generated `scripts.inc` back so git tracks the current output.

## Known limits (v1)
- **Vocabulary:** route terrain, ledges, shores (grass banks, beaches, water rocks), flora (flowers, boulders, saplings), building stamps on `gTileset_General` (houses, the lab and the wide house need `gTileset_Petalburg`), the north-south plank bridge (Petalburg and Rustboro maps) and grass-topped cliffs with levels, stairs and cuttings (General's rock family). Rock-topped mountains (Route 111's `071` plateaus), cliffs straight into water, the cliff-ledge joint pieces (`08F 095 096`), side stairs, rocky shores, pond shores by shape, Rustboro's paved city buildings, hedges, fences, east-west and surf-under bridges stay literal (`#`) or are hand-painted in Porymap. Extract keeps every cliff as `#` (levels aren't recovered). The 16 vanilla ledge groups that meet cliffs (Route 118's terraces and five others, listed in `tests/ledge_pieces.py`) extract as `#`.
- **Engine model:** doesn't cover sideways stairs, ice, currents, bikes or boulders. People block where they stand; a wanderer is judged at home (route numbers), tile by tile for exits (checker), or as its whole range (walker). Buried trainers (Lavaridge Gym) aren't modelled as blockers. Story maps can take control on warp-in, and conformance skips those.
- **Exact match:** isn't the same as looking right. Always review renders and in-game shots.
